# AGENTS.md

Buylist is a realtime shared shopping-list PWA running on a **single Cloudflare
Worker**: D1 holds the master data, one Durable Object per list holds the live list
state and broadcasts it over WebSockets, and Gemini/Groq power the AI features.
See [`README.md`](./README.md) for the architecture diagram and the full API table —
this file only covers how to work in the repo.

> **The codebase is German.** Identifiers, comments, UI copy and API error messages
> are written in German (`erledigt`, `menge`, `zutaten`, `aktiveGerichte`,
> `hinzugefuegtVon`). Keep it that way — do not "fix" it to English. Only
> infrastructure terms (worker, session, broadcast, …) are English.

## Commands

Node 22 (same as CI).

```bash
npm install
npm run dev                    # wrangler dev on http://127.0.0.1:8787
npm run typecheck              # tsc --noEmit
npm test                       # unit tests (node:test)
npm run db:migrate:local       # apply D1 schema to .wrangler/state
node scripts/realtime-test.mjs # integration test, needs a running `npm run dev`
npm run deploy                 # wrangler deploy
```

Local secrets live in **`.dev.vars`** (template: `.dev.vars.example`), *not* in
`.env` — that is what wrangler reads. In production they are set with
`wrangler secret put`.

## Hard rules

- **No runtime dependencies.** `package.json` intentionally has `devDependencies`
  only; the crypto (PBKDF2 password hashing, Web Push aes128gcm) is hand-written on
  `crypto.subtle` on purpose. Ask before adding an npm package.
- **No build step for the frontend.** `public/` ships exactly as it sits in the repo.
- **No linter or formatter is configured.** Follow `.editorconfig` (2 spaces, LF,
  UTF-8, final newline) and the style of the surrounding file: double quotes,
  semicolons, named exports.
- **Do not commit or push** unless you were asked to. Default branch is `main`.
- **Never put secrets in a tracked file.**

## Backend patterns

Reuse what exists instead of rebuilding it:

- Every protected handler follows the same chain: `withAuth()` (`src/session.ts`) →
  `checkListAccess()` (`src/lists.ts`) → `listNotFound()` / `readJson()` / `json()`
  (`src/util.ts`).
- Lists the user is not a member of return **404, never 403** — the existence of a
  foreign list must not leak.
- Compare free text with `normKey()` (`src/util.ts`, mirrored in
  `public/app-core.mjs`) — never with raw `===`.
- Sanitize and truncate input at the edge (the `slice` limits in the handlers and in
  `src/do/shopping-list.ts`), not deep inside the logic.

## Gotchas

- **The Durable Object authorizes nothing.** `ShoppingListDO` trusts the
  `x-user-id` / `x-display-name` headers that the Worker sets itself in `handleWs`
  after checking session and membership (incoming headers of the same name are
  deleted first). Any new DO endpoint needs its own check in the Worker in front
  of it.
- **The list blob is schemaless and may only grow additively.** New fields must be
  optional (`history?`, `aktiveGerichte?`, `quelle?`) so existing DO blobs keep
  parsing — there is no migration mechanism for DO storage.
- **A new frontend helper touches three places:** `export` it in
  `public/app-core.mjs`, add it to the `window.BC` object at the bottom of that file,
  and destructure it at the top of `public/app.js`.
- **A new static file must be added to `SHELL_URLS` in `public/sw.js`**, otherwise it
  is missing offline.
- **`public/data/categories.json` is not a frontend-only asset.** `src/recipes.ts`
  and `src/parse.ts` import it and build the `enum` of their Gemini/Groq response
  schemas from it. Changing category ids means changing both sides.
- **Bump `CACHE_VERSION` in `src/recipes.ts`** whenever the system prompt or the
  response schema changes there — otherwise `recipe_cache` keeps serving recipes
  generated by the old prompt.
- **Count the rate limiter last.** As in `handleGenerate`, check auth, validate the
  body and look in the cache *before* hitting `RATE_LIMITER_DO`, so cache hits and
  invalid requests do not burn quota.
- **New D1 migration** = a new numbered file in `migrations/`, then
  `npm run db:migrate:local`. **New Durable Object class** = export it from
  `src/index.ts` *and* add a `migrations` tag with `new_sqlite_classes` in
  `wrangler.jsonc`.
- **Missing API keys are expected behaviour, not a bug.** Without
  `GEMINI_API_KEY` / `GROQ_API_KEY` those routes answer with a clear message from
  `missingSecret()`; without VAPID keys push is a no-op and the UI hides the toggle.

## Tests

`node:test`, no external framework.

- Unit tests for pure logic sit next to their module (`src/**/*.test.ts`, run through
  `tsx`; they are excluded from the typecheck in `tsconfig.json`).
- Frontend helpers are tested in `test/*.test.mjs`, importing `public/app-core.mjs`
  directly.
- Logic that should be testable belongs in a pure module without DOM or `Env` —
  the way `src/do/list-logic.ts` was pulled out of the Durable Object.
- Anything that needs the Worker runtime, D1 or WebSockets goes into
  `scripts/realtime-test.mjs`.

## Definition of done

1. `npm run typecheck` and `npm test` pass.
2. For changes to the API, the WebSocket flow or the DO: `node scripts/realtime-test.mjs`
   against a running `npm run dev`.
3. For frontend changes: check it in the browser — two windows on the same list show
   the realtime path.
4. If routes, modules or setup changed, update `README.md` in the same pass; it is
   currently accurate and should stay that way.
